# LLMRE two-stage adaptation: formal 300-passage run

This directory records a new external comparison, separate from the preceding trial directory. The historical instructions copied the whole comparison workspace into a PyCharm project. For a new portable run, preserve this directory structure, open 01_Run_LLMRE_Adaptation.py, and fill only the empty credential placeholder. The default is the full 300-record run; running the development set first is unnecessary. Python 3.10+ and the standard library suffice; no local LLM download is needed. Do not copy an older result directory into the new run.

Startup checks validate development/test disjointness, unique IDs, seven Schema patterns, credential presence and API connectivity. Outputs go to Results/Formal_300. Each successful request and record is stored in SQLite; rerun the unchanged script/configuration to resume. Changed inputs, prompts, program, model or key parameters prohibit mixing caches. Do not edit inputs while running.

Stages: NER; synonym assessment and shared concept clustering; hierarchy assessment between clusters; seven-pattern candidate generation; independent scenario-based judgment using full source text. Relations require a continuous evidence span and the actual endpoint surfaces. Synonym expansion is limited to forms directly expressed in that evidence; relations are not copied to other disease names or inherited by upper concepts. See Method_Mapping_and_Adaptation.md.

Each synonym, hierarchy or relation candidate receives an independent request, as in the author implementation. Five passage threads share a minimum one-second request-start interval. Unlike the preceding V4 batched-candidate condition, this can require thousands of calls and several hours; cost/time depend on candidate counts, latency and retries. Progress and ETA are displayed; complex passages can temporarily leave completed-record counts unchanged. There is no fixed candidate truncation. API errors receive at most six retries. An incomplete run does not export a formal evaluation TXT; restart processes only unfinished passages.

Run 02_Evaluate_Results.py only after Completion_Status.json reports complete=true and success=300 and Predictions_300.txt exists. Evaluation uses the same 300-record Gold and strict set matching as ECKE, validating prediction fingerprints, counts, order and Gold quality first. Gold is isolated in Evaluation_Only and is not read by prediction. Archive the entire completed Results/Formal_300 directory.

Describe this as LLMRE adapted to the wasting-thirst task with a common Qwen backbone, not a strict rerun on the original biomedical data and Llama 3.1 70B. Disclose the type/Schema, topic evidence, and synonym-expansion adaptations; do not directly compare these scores with the original paper's scores.
