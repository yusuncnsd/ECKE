# 方法来源与任务适配说明

来源：Lei Zhao, Ling Kang, Quan Guo. *Zero-shot document-level biomedical relation extraction via scenario-based prompt design in two-stage with LLM*. Computational Biology and Chemistry, 2026, 123:108978. DOI: https://doi.org/10.1016/j.compbiolchem.2026.108978 。作者代码：https://github.com/tyrone1979/LLMRE 。参照论文第 2.1、2.2 节以及作者代码 `src/task_ner.py`、`src/relation.py`、`src/task_re.py`、`meta/prompt_templates.json`。

| 原方法机制 | 本实验实现 | 必要适配或差异 |
|---|---|---|
| 零样本、两阶段框架；NER 与规范化先于 RE | 阶段一识别原文实体、判别同义并建共享概念簇、判别上下位；阶段二生成 Schema 兼容候选并判别 | 输入换为固定的消渴古籍 300 条，不使用训练参数或测试 Gold 调整提示 |
| 场景化提示，包含语境、任务、正例、反例、输出格式 | `Inputs/提示.json` 分别固定实体、同义、上下位和关系提示 | 例子和实体定义换为本研究既定的七类实体、七种关系及专题边界 |
| 同义实体共享索引，代表实体参与关系候选，成立后扩展到同义实体 | 同义边形成确定性概念簇；每个簇选一个代表进入候选生成；关系输出列明证据中的实际别名 | 仅扩展至同一连续原文证据直接支持的表面形式；不向其他共现病名机械复制 |
| 上下位识别与上位实体过滤 | 不同义概念簇之间判别上位/下位，父簇传入关系判断；关系必须给出直接证据 | 原文直接指向上位病名时保留该关系；不能仅因下位关系成立而复制到上位病名，避免与固定 Gold 规则冲突 |
| 按 Schema 生成候选，逐候选独立询问 LLM | 七种既定 Schema 逐候选发送完整原文与正负场景；不把类型兼容直接当作关系成立 | 原论文的化学物、基因、疾病关系改为消渴专题关系；使用同一 Qwen 模型控制与 ECKE 的基础模型差异 |
| 作者主实验本地 Llama 3.1 70B、原生物医学数据集 | 在线 `qwen-plus-2025-07-28`、温度 0、固定随机种子、300 条独立测试集 | 属于算法结构的任务适配实现，不是对作者原始数值结果的复现 |

证据约束是本研究统一标注口径，不是将 ECKE 的词表锚定、显式—隐式融合等核心模块注入对比方法。预测脚本不读取领域词表、ECKE 预测或 Gold。实体必须有原文逐字证据；关系成立须有包含实际头尾端点的连续原文证据。输出保留候选、概念簇、上下位判断、实体与关系预测，以便审计。

同义和上下位候选逐个请求，使用原作者代码的候选级问答粒度；实际接口、JSON 格式和续跑缓存属于运行环境适配。若论文报告该结果，应公开上述差异，不写作“完全复现原论文设置”。
