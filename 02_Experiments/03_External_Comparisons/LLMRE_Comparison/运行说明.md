# LLMRE 两阶段方法的消渴任务适配：正式 300 条

本文件夹是一次全新的外部对比实验。请将整个 `对比33` 复制到 `D:\PyCharm 2025.1.3\LLM-TCM\对比33`，打开 `01_运行LLMRE任务适配.py`，只填写文件顶部的 `API密钥 = ""`，直接运行。默认就是完整的正式 300 条，不需先运行开发集。建议 Python 3.10 以上；只使用标准库，不下载大模型或安装额外依赖。不得将旧 `对比3` 的 `结果` 目录复制进来。

程序启动时先核验 100/300 清单互斥、ID 唯一、七种 Schema、密钥与接口连通性，然后逐条运行。结果写入 `Results/正式300`。每个请求与每条成功记录都进入 SQLite 续跑缓存；意外中断后用原脚本、原配置再次运行即可续跑。输入、提示、程序、模型或关键参数变化时会拒绝混用缓存。请不要在运行中修改脚本或输入。

本实现沿用原论文的两阶段思想：实体识别；同义判别并建立共享概念簇；对不同簇识别上下位；按七种 Schema 生成关系候选；依据正负场景和完整原文逐候选判别。关系输出须包含原文连续证据片段与实际头尾表面形式。只对同一证据中直接出现的同义表面形式展开关系，不向同条其他病名机械复制；上位概念也不能仅凭层级继承下位关系。这是遵守本研究固定专题边界与 Gold 标注口径的任务适配，详情见 `方法映射与边界.md`。

作者实现对候选分别向模型提问。本版同义、上下位、关系也都是每个候选一个独立请求，五个条文线程共用至少 1 秒的请求启动间隔。与 V4 合并多个候选的请求相比，正式运行预计需要数千次请求，可能持续数小时，具体用时及费用取决于实体数量、接口延迟与重试。程序会持续显示完成进度和预计剩余时间；复杂条文处理期间完成条数可能暂时不变。无固定候选数截断。接口错误最多重试六次，最终失败不会导出正式评价 TXT，重启只补跑未完成条文。

只有 `完成状态.json` 显示 `complete: true`、`success: 300`，且生成 `预测300.txt` 后，才运行 `02_评价结果.py`。评价脚本使用与 ECKE 相同的 300 条盲标 Gold 和严格集合匹配规则，先核验冻结预测指纹、数量、ID 顺序与 Gold 质量，再输出实体和关系 Precision、Recall、F1 等结果。Gold 位于独立的 `评价专用` 目录，预测脚本不读取该目录。正式运行结束后，请把整个 `Results/正式300` 归档回主实验的外部对比资料目录。

本实验不能称为在作者原生物医学数据集及 Llama 3.1 70B 上的严格复现。论文中建议标注为“LLMRE（消渴任务适配，统一 Qwen 基础模型）”，并说明七类实体、七种关系、专题证据边界和同义扩展规则的适配。不要将本实验分数直接与原论文报告的分数比较。
