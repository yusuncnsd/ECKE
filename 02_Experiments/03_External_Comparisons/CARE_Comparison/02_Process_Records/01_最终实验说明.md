# CARE第二版最终实验说明

## 第二组外部对比：CARE第二版实验设计

最终采用CARE中文低资源适配复现，并在100条开发数据上校准解码阈值。论文中可以使用CARE（复现）作为表格名称，但方法说明必须披露适配条件，不能声称沿用原作者全部训练条件。

### 固定条件

- 作者代码commit：93ea51306a94b617deb412e9bb8372a94a59dacf；论文与许可证保存在原始资料目录。
- 编码器：google-bert/bert-base-chinese；revision：8f23c25b06e129b6c986331a13d8d025a92cf0ea。
- 保留作者co-attention和分类器结构；分类器训练保留logits以计算稳定损失。
- 七种实体类型、七种合法关系模式、六个关系标签；机器Schema以代码包data/xiaoke_schema_v5.json为准。
- 100条专家开发数据用于监督训练与阈值开发；这是外部监督基线条件，不表示本文LLM主方法进行了参数训练。
- 开发数据固定五折，每折80条训练、20条验证，验证ID覆盖100条且互斥。
- 固定100轮；学习率0.0001、Adam、dropout 0.1、梯度裁剪0.25、有效batch8/microbatch1；启用梯度checkpoint。
- 正负有效网格分别取softplus均值，再等权平均；没有正例的头只取负例均值。实体使用上三角文本网格，关系使用全部有效文本对网格。
- 五折训练种子20260823；正式三个种子20260823、20260824、20260825，分别以全部100条训练并预测固定300条。
- 最大512 tokens，超长不静默截断；中文按字符WordPiece对齐原文证据。
- 服务器记录环境torch 2.8.0+cu128、transformers 4.55.4、RTX4090D。没有调用LLM API。

### 第二版阈值选择

预先固定网格0.5、0.8、0.95、0.99、0.999、0.9999，实体与关系组合共36组。复用五折最终模型，在100条折外记录上推理，只使用开发Gold评分。候选必须使两项汇总Micro-F1都高于0.5/0.5，随后最大化两项F1的算术平均值，平分按关系Precision及阈值确定。

选定实体阈值0.9999、关系阈值0.9999。五折选择后的实体F1为0.3298611111、关系F1为0.0641025641。以上数据用于参数选择，不是独立验证性能。具体36组结果和绑定指纹在results_calibrated_v1/threshold_selection.json中。

### 评价与报告

正式Gold包含869个实体集合项、508个关系集合项。实体严格匹配surface+type；关系严格匹配有向head+relation+tail；列表顺序无关，重复项按集合折叠。主要报告Micro-P/R/F1，三个运行算术均值及样本标准差，不把900次预测作为900条独立测试样本。

逐种子F1置信区间按条文bootstrap5000次、种子20260822；配对分析复用原脚本10000次bootstrap与10000次置换，每任务仅对三个CARE种子作Holm校正。关系Macro-F1沿用原评价的六个标签口径，并非另行将七种类型模式重新划类。

第二版是在第一版测试指标已经计算后开展的开发集校准。实际校准程序没有读取测试Gold，没有用测试答案选择阈值；论文应如实披露实验顺序，不声称此前从未评价测试集。

## 第二版最终实验运行过程

1. 固定100条开发监督、互斥300条测试输入、唯一Schema及五折划分。
2. 保留作者协同注意力与分类器结构，使用中文BERT与用户批准的正负样本平衡损失；五折和三个正式种子均训练100轮。
3. 采用CARE_resume_decode.py的等价索引解码，合法Schema连接和严格集合输出保持一致，不截断预测。
4. 复用五折模型，仅在100条开发折外记录上比较预先固定的36组实体/关系阈值；选定0.9999/0.9999。
5. 三个已训练的正式模型分别用冻结阈值预测同一300条输入，成功记录各300条；云端校准程序未读取测试Gold。
6. 本地下载原始结果包，对代码来源、文件指纹、ID、证据区间与Schema执行核验；统一评价冻结Gold，得到实体F1=38.66±3.42%、关系F1=6.13±2.22%。

### 原始证据所在位置

- results_calibrated_v1：三个种子的原始预测、完成记录、绑定、正式审计和完整开发阈值选择记录。
- results_fixed100：生成第二版所用模型的八组绑定与训练日志；五折complete.json中的0.5开发计数是校准程序的复核依赖，并非另一套正式测试结果。
- 05_运行日志：第二版校准原始日志及云端原始结果包SHA校验文本。
- 03_结果文档：云端第二版原始结果包、统一评价和论文报告。

### 如实披露的边界

第二版校准实施前，测试集曾有过一次评价；此次阈值选择使用开发数据，未使用测试Gold，但不声称测试集此前完全未被评价。五折输出参与参数选择，其选择后得分不是独立验证性能。

按用户要求，模型权重未留存，旧预测、旧评价入口、旧说明和非最终输出日志已移除。模型需要重新训练才能重新推理；现有原始预测可以直接重新评价。

提交目录的asset_manifest只剔除了旧评价入口和旧README；训练代码、数据、配置、第二版预测及云端原始绑定均未改写。原训练manifest指纹在submission_cleanup及最终条件中记录，原云端manifest快照保存在第二版原始结果包内。

## 运行与资料使用

### 查看结果

直接阅读03_Result_Reports/CARE第二版_正式结果报告.md。JSON指标单位为0到1；报告表格单位为百分比。CSV是逐种子P/R/F1、TP/FP/FN和置信区间。

### 本地重新评价（不训练、不请求API）

在01_实验代码目录运行：

```powershell
python CARE_evaluate_second.py
```

该入口会定位项目主实验中的冻结300条Gold与ECKE冻结预测，校验指纹并重建本目录结果文档。正式Gold保持项目公共原始位置，不额外复制。

### 从头复现（仅在权重丢失时）

需要原revision中文BERT、torch2.8.0+cu128和transformers4.55.4的CUDA环境；恢复整个01_实验代码内的相对结构，不修改绑定源文件。八个checkpoint必须位于CARE_Balanced/results_fixed100原路径。

若完全重训，应在新服务器运行副本中清空已有results_fixed100/results_calibrated_v1元数据，保留原始归档与正式预测，依次执行：

```bash
python -u CARE_Balanced/CARE_run.py quick --model /root/autodl-tmp/AutoDL_CARE/models/bert-base-chinese
python -u CARE_resume_decode.py --model /root/autodl-tmp/AutoDL_CARE/models/bert-base-chinese
python -u CARE_calibrate.py --model /root/autodl-tmp/AutoDL_CARE/models/bert-base-chinese
```

前两步重建共享固定100轮模型，第二步的0.5正式预测仅是旧入口的中间产物，不作为本次论文最终结果；第三步重现第二版阈值选择与最终预测。不同GPU或依赖版本可能产生数值差异，应记录为新的复现运行，不能覆盖已冻结正式预测。不要在当前归档目录直接删除或重训。
